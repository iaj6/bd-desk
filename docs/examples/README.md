# Example agent output

Illustrative deliverables, so you can see the **shape** of what the pipeline produces
before provisioning any agents or spending anything.

- **[`dossier-cascade-provisions.md`](dossier-cascade-provisions.md)** — a pre-engagement
  dossier: the seven sections plus the `<people>` machine block the CRM ingests. This is
  exactly what `npm run demo` attaches when you click **Research** on a company. A real
  graded run produces the same shape from live web research (and drops the "Demo mode"
  notice at the top).
- **[`sponsor-profile-calderwick.md`](sponsor-profile-calderwick.md)** — a sponsor
  profile: the portfolio enumeration with `→ ADD` flags, plus `<people>` and `<portcos>`
  machine blocks. The `→ ADD` portcos are what auto-feed the board.
- **[`eval-scorecard.json`](eval-scorecard.json)** — the shape `npm run eval` writes to
  `evals/runs/`: per-task grader verdict, the deterministic checks, and a blended score
  (`(verdict score + check pass-ratio) / 2`). The numbers here are illustrative.

The two markdown files are generated by demo mode, so they are **canned and labelled as
such** — no model was called. Once you wire up real agents (see [Setup](../../README.md#setup)),
a real dossier, sweep report, and eval scorecard look the same, just sourced from live
research. Machine-block format lives in [`skills/bd-machine-blocks`](../../skills/bd-machine-blocks).
